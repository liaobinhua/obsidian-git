# Android 安装与使用

## 0.1 Objective/Coverage

本文说明 Wudao Git Android 包的安装、手机令牌、首次下载、日常上传、冲突处理、恢复和真机验收。0.2.0 为候选版本；自动化验证不代表完成真机验收。

## 1. 准备电脑数据

在电脑上审阅需要同步的文章，提交并推送到私有文库仓库。尚未提交或尚未推送的文件不会出现在手机下载中。手机连接的是文章仓库，不是插件源码仓库。

## 2. 安装 Android 包

1. 在 Android Obsidian 新建空白文库，例如 `Documents/wudao-test`。如果生成欢迎文章，先将其移到其他地方保留。
2. 从本项目 Releases 下载 `wudao-git-0.2.0-android.zip`。
3. 在手机文件管理器启用显示隐藏文件，创建 `<文库>/.obsidian/plugins/wudao-git/`。
4. 解压并把 `main.js`、`manifest.json` 和 `styles.css` 放进该目录，避免多嵌套一层 ZIP 名称目录。
5. 重新打开 Obsidian，在第三方插件中启用 Wudao Git。不要同时启用其他同步同一文库的插件。

手机需要提供 Web Crypto 的 Android System WebView。出现相关提示时先更新 WebView 和 Obsidian。

## 3. 配置并首次下载

在 GitHub 创建手机专用细粒度令牌，选择 `Only selected repositories` 中的文章仓库，授予 `Contents: Read and write`，设置到期时间。不要提供仓库管理权限或将令牌粘贴到聊天。

在插件设置中填写 `owner/repository` 和分支，在 SecretStorage 中添加令牌并选择其引用名称，点击保存。保持默认的仅下载模式，运行“首次下载或检查远端更新”，核对文件计划后应用。检查文章、模板和附件后再启用“允许上传”。模板目录可设为 `90-模板`，附件目录可设为 `99-附件`。

## 4. 日常使用

写作前检查远端，写完运行“检查并上传选中文件”，查看内容、选择文件并填写说明，再核对目标及删除清单后确认上传。只有远端确认成功后才会显示完成。

离线可以写作和审阅快照。恢复网络后仍需显式上传；如果远端已改变，先重新下载审阅。仅下载模式仍可能按已确认的远端删除计划修改本地文件，它不是“永不删除”的文件浏览器。

换设备前完成上传，另一设备先拉取再写作。Mac 有未提交改动或未推送提交，而手机已经上传时，应停止并在电脑处理差异；不要反复提交、强制重置或强制推送。

## 5. 冲突、删除与恢复

同一文件两端都修改时，先点击“查看”比较三个版本，再选择保留手机版本、采用远端版本或保留两份。保留两份时，原路径采用远端，手机原文另存为 `.local-copy` 文件；重名时增加编号。

删除需要逐项勾选；两项以上还需额外确认批量删除。冲突选择保留手机内容时，不执行那一项原文删除。

同步中断后运行“恢复或核对中断的同步”：下载中断会根据写前日志恢复；后续用户编辑会保留，必要时生成 `.recovery-copy` 原文备份。首次下载的新文件没有本机原文，部分写入后需检查当前内容，并可从 GitHub 恢复完整版本。上传超时先只读核对分支；仍待上传时会重新展示同一提交的确认窗口。远端竞态需要重新下载审阅，不强制覆盖。

本地状态损坏时，保留文章和 `.obsidian/plugins/wudao-git/` 状态文件，先复制文库备份再处理，不要删除状态文件来绕过提示。状态、草稿和恢复备份可能包含文章正文，以普通本机文件保存，不应上传到 Git 或分享。

## 6. 真机验收

在测试仓库和空白测试文库验证：包能启用、仅下载不产生远端提交、中文和带空格路径完整、图片能打开、仅选中文件上传、电脑和手机往返同步、冲突保留两份、删除确认、断网及关闭应用后的恢复，以及错误或过期令牌不会清空文章。

发现失败时保留测试文件及脱敏错误信息，先修复候选版本，再连接正式文章仓库。
