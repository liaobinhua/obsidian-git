# Android 安装与使用

## 0.1 Objective/Coverage

本文说明 Wudao Git 0.3.0 的 Android 安装、原位接入、升级迁移、暂存上传、冲突与恢复。Android 安装包仍为候选版本，自动化检查不代表完成真机验收。

## 1. 安装与升级

从公开插件项目 Releases 下载 `wudao-git-0.3.0-android.zip`。先备份文库，停用插件并彻底退出 Obsidian；仅替换 `<文库>/.obsidian/plugins/wudao-git/` 中的 `main.js`、`manifest.json` 和 `styles.css`。保留该目录现有配置和同步记录。重新启动并启用插件，设置页应显示 0.3.0。

旧版的配置、基线、草稿、暂存快照、待核对上传与恢复日志会迁移到 `<Obsidian 配置目录>/wudao-git/`，旧副本保留。长期状态目录与程序目录独立；以后替换程序不会要求重建文库。原令牌引用继续使用，无需重新生成令牌，也不会修改其有效期。

不要用 Mac 安装包覆盖 Android 版本。手机需提供 Web Crypto 的 Android System WebView，Obsidian 最低版本见安装包 manifest。

## 2. 连接已有文库

在插件设置中填写文章仓库 `owner/repository` 与分支，并选择手机本机 SecretStorage 中的令牌引用名称。插件源码仓库与文章仓库可以不同。细粒度令牌只选择文章仓库并授予 `Contents: Read and write`；有效期由你决定，可以保留现有不过期令牌。不要将令牌值填写为引用名称，也不要写入笔记。

保存设置后打开“版本控制”。有效旧记录会继续使用；首次连接或记录缺失时，点击“连接现有文库”比较当前目录：相同内容建立基线，仅本地文章保留等待你选择上传，仅远端内容等待下载，同名内容不同需选择本地、远端或保留两份。确认前不修改文章或 GitHub；缺少历史基线时不会推断删除。

保持默认仅下载模式，核对后确认连接。目录会按安全远端结构补齐，包括只有 .gitkeep 占位的分类目录；占位正文和隐藏配置本身不下载，预览中展示排除原因。模板目录可设为 `90-模板`，附件目录可设为 `99-附件`。

## 3. 查看状态、差异与历史

点击 Git 图标或运行“Wudao Git：打开版本控制”。工作区变化比较当前编辑与暂存快照；已暂存列表显示准备上传的固定内容。当前文章状态区分已暂存、另有工作区变化及不在同步范围。面板自动刷新本地状态，离线可查看；远端状态需手动检查，上次检查时间不能代表 GitHub 此后没有变化。

点击“查看差异”先显示本地快照。需要未缓存的基线正文时点击“联网补全基线”；网络或令牌无效时继续显示本地内容并说明基线未能获取。点击“提交历史”读取 GitHub 的真实提交，再选择提交、文件查看前后内容。二进制附件展示大小等信息。

## 4. 提交与多设备使用

写作前点击“检查远端”，逐项处理变化并应用。写完选中文件，点击“暂存选中文件”；暂存后继续编辑会作为新的工作区变化，暂存内容不被替换。勾选已暂存项时仅上传勾选项，未勾选时使用全部允许的暂存内容。

在设置中开启“允许上传”并保存，填写说明后点击“提交并同步”，在确认窗口核对文件与删除项，最后确认上传。手机离线暂存是待上传快照，只有 GitHub 确认分支更新后才显示上传完成。取消暂存只撤销快照选择，不删除文章。

另一设备已经上传时，先检查远端并处理冲突。旧暂存快照会保留；基线变化导致快照过期时，先查看旧快照，需要保留的内容另存后取消暂存，再重新审阅和暂存。插件不会把过期快照直接覆盖到新远端。

换设备前完成上传，另一设备先拉取再写作。只有本地保存或暂存，另一台设备不会收到。插件版本升级仍从 Releases 安装对应平台包，文章同步不会更新插件程序。0.3.0 不自动同步。

## 5. 冲突、删除与恢复

同名文章不同内容时，先查看差异，再选择保留本地、采用远端或保留两份；保留两份会在原路径应用远端，手机原文另存为 .local-copy 文件。删除须逐项确认，批量删除另有确认。选择保留本地时不执行该项原文删除。

下载或上传中断后，运行“恢复或核对中断的同步”。写前日志会恢复已批准的操作；后续编辑保留，必要时生成 .recovery-copy 原文备份。新下载文件没有本机原文，部分写入后可从 GitHub 恢复完整版本。上传超时先核对远端，重试原提交仍需确认。

记录损坏时使用“修复同步记录并重新比较”。先只读比较文档，确认后保留并额外备份原始记录，再建立新状态。备份、草稿和暂存快照可能包含正文，只保存于本机，不应加入 Git 或分享。未知新版格式会停止处理，不能通过修复命令覆盖。

## 6. 真机验收

使用测试仓库验证：旧文库带未上传文章升级、已有文档原位接入、暂存后继续编辑再重启、只上传选中快照、中文路径与附件、两端往返、保留两份、删除确认、断网恢复、损坏记录修复及无效令牌。验收期间保留原文与状态备份，不以清空文库绕过错误。
